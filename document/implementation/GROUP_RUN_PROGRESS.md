## 4. Quyết định kỹ thuật đã chọn

### Database (đã implement)
- Model `Run` (table `runs`), `RunExecution` (table `run_executions`), theo Section 17 DB-C01–C10 (bản đã sửa) của `AnD_Database_Group_Run`.
- FK: `projectId → Project.projectId`, `environmentId → Environment.environmentId`, `createdBy → User.userId`, `apiId → ApiConfiguration.apiId`, `runId → Run.runId`. Tất cả RESTRICT/CASCADE.
- Domain cố định dùng `VARCHAR + CHECK` qua raw SQL, KHÔNG tạo bảng catalog riêng.
- Batch max 20 API: enforce ở application layer (`MAX_BATCH_EXECUTIONS` trong `create-run.dto.ts` qua `@ArrayMaxSize`), KHÔNG phải DB CHECK (DB-C01) — đã áp dụng ở Phase 2.
- `error_reason_code` domain: TIMEOUT / DNS_ERROR / TLS_ERROR / CONNECTION_ERROR / UNKNOWN_EXECUTION_ERROR / HTTP_ERROR.
- `api_version`/`database_version`: NOT NULL, fallback UNKNOWN, chốt (freeze) tại thời điểm Execute được tiếp nhận, không sửa đè Run cũ (RUN-009).
- Execution Status (PENDING/RUNNING/COMPLETED/SKIPPED/INTERRUPTED/NOT_EXECUTED) tách biệt hoàn toàn với Execution Outcome (RESPONSE_RECEIVED/RUN_ERROR/SKIPPED).
- Unique: `uq_run_executions_run_id_api_id`, `uq_run_executions_run_id_execution_order`. Index: `idx_runs_project_id_created_at`, `idx_run_executions_api_id_created_at`.
- `skip_reason_code` CHECK cho phép cả `MISSING_FULL_URL` (CONFIRMED) và `MISSING_REQUIRED_INPUT` (Design Proposal, DC-01 chưa chốt) — xem comment trong migration.sql.
- Không thêm cross-column CHECK (vd liên hệ giữa execution_outcome/status/skip_reason_code) — để service layer enforce, tránh chặn nhầm write hợp lệ.
- `responseBodySizeBytes`/`responseBodyStoredBytes` dùng `Int` (không `BigInt`) — nhất quán với schema hiện tại, tránh friction JSON serialize.

### Backend (đã implement)
- Endpoint đã tạo (khớp AnD API doc):
  - `POST /api/v1/projects/:projectId/runs` — createRun (Single hoặc Batch)
  - `GET /api/v1/projects/:projectId/runs` — listRuns (Project Test Runs, UI-RUN-07)
  - `GET /api/v1/projects/:projectId/runs/:runId` — getRun (+ executions con)
  - `GET /api/v1/projects/:projectId/runs/:runId/executions/:executionId` — getRunExecution (UI-RUN-05)
  - `GET /api/v1/projects/:projectId/apis/:apiId/run-executions` — listApiRunExecutions (UI-RUN-08)
  - `RunModule` đã đăng ký trong `apps/api/src/app.module.ts`.
- Run Execution Engine: dispatch tuần tự (Single = 1, Batch = N theo thứ tự đã chọn, tối đa 20 — enforce ở DTO), không auto-retry, không follow redirect (`redirect:"manual"`); phân loại HTTP 2xx/3xx→RESPONSE_RECEIVED, 4xx/5xx→RUN_ERROR, lỗi transport→RUN_ERROR với `http_status = null`; Batch thiếu Full URL/input → SKIPPED (không tạo request, reason `MISSING_FULL_URL`/`MISSING_REQUIRED_INPUT`); Single thiếu → 422, không tạo Run. Credential thật giải mã bằng `decryptSecret()` chỉ để gửi request thật, KHÔNG bao giờ lưu plaintext vào `run_executions` (chỉ lưu `requestHeadersSafe` đã redact qua `redactHeaders()` — chỉ mask header Authorization).
- Dispatch là fire-and-forget trong-process, gọi ngay sau khi transaction `createRun` commit, KHÔNG await trong HTTP response — client tự poll `getRun`/`getRunExecution` để lấy trạng thái mới nhất. KHÔNG có job queue/cross-process recovery — INTERRUPTED chỉ xử lý lỗi engine bất ngờ trong cùng process.
  - **Giới hạn đã biết (chấp nhận được, không phải bug):** vì dispatch chạy trong cùng Node process với API server, nếu server restart/crash giữa lúc đang dispatch một Run, các `RunExecution` còn PENDING/RUNNING sẽ bị kẹt vĩnh viễn ở trạng thái đó (không tự chuyển INTERRUPTED) — chấp nhận theo đúng phạm vi REQ-RUN hiện tại (không yêu cầu job queue/recovery riêng).
- Response body: TEXT (theo content-type) lưu tối đa 1MB + cờ `isTruncated`; BINARY chỉ lưu metadata, không đọc body vào memory.
- Copy pattern transaction/`assertProjectActive`/`auditWriter.record`/Swagger từ `environments.service.ts`+`environments.controller.ts` — đã áp dụng nhất quán.
- Quyền truy cập: `ProjectAccessGuard` (không giới hạn ADMIN) cho toàn bộ Run endpoints — Run là hành động "làm việc" (giống sửa Request Input/API Configuration), không phải hành động cấu hình hệ thống như Environment/User management.

Ô điền dùng kỹ thuật overlay `<pre>` màu chồng dưới `<textarea>` chữ trong suốt (kỹ thuật chuẩn khi không dùng code-editor dependency). 6 token màu riêng (`--color-json-*` trong `index.css`) tách biệt khỏi token trạng thái validate (`--color-success`/`--color-error`) để giữ đúng ngữ nghĩa.

### Frontend (đã implement — Batch Run UI-RUN-04/05/06)
